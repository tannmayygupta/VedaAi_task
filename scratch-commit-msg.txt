Phase 7: error and empty states, found via an 11-agent resilience audit

Ran a broad read-only audit across the whole app before writing any code,
covering every area (upload, both API routes, mapping-page data-fetching,
PDF rendering, empty-state UI, grading math, timeouts, error normalization,
existing test coverage, and Figma) rather than just the 4 PRD bullets.

Implemented the confirmed gaps:
- Empty-questions state (NoQuestionsFoundState) for a genuinely empty but
  valid extraction result, instead of a blank panel and a nonsensical
  "0/0 (0%)" summary.
- In-place retry for extraction failures: "Try Again" re-runs the pipeline
  against the same already-uploaded blob URLs instead of navigating back to
  the upload screen and losing them (a deliberate, logged deviation from the
  PRD's literal wording, since the files are already durably uploaded by the
  time this screen is reachable).
- Fixed a silent unhandled promise rejection in UploadSlotCard (a corrupted
  file that passed validation but failed page-count parsing left a stale
  "accepted" file chip with no error shown).
- Fixed scoreTier mislabeling a correctly-answered zero-mark question as
  "wrong" (red styling).

Added a page-level test file for src/app/mapping/page.tsx (didn't exist
before), which was the actual gap behind "partial failure = full failure"
only having hook-level, not UI-level, test coverage.

Verified two real failures live in the browser against real infrastructure:
a nonexistent answer-sheet blob URL (full pipeline -> error screen -> Try
Again retry -> Back to upload, all working), and a renamed-away pdfjs
worker file (an audit-flagged "untested" case) - confirmed it surfaces a
clear error message rather than hanging silently.

Deferred, real but out-of-scope findings logged as known limitations rather
than silently dropped: generic (non-code-differentiated) error messages, no
client-side timeout/escape-hatch on the loading screen, and PDF page-index
bounds-checking for hallucinated indices. Full findings and reasoning in
docs/DECISIONS.md.

Also signs off Phase 6 (Mapping Screen UI core) in docs/TRACKER.md.
